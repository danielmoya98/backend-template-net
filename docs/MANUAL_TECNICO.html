1. Resumen Ejecutivo & Visión General

El Enterprise .NET Starter Kit es una base de código de ingeniería avanzada diseñada para construir aplicaciones backend escalables, mantenibles y altamente seguras bajo .NET 10 y C# 13.

🏆 Certificación de Calidad y Seguridad
La solución ha sido auditada exhaustivamente: cuenta con 0 vulnerabilidades de paquetes (CVEs), 0 advertencias de compilación y una suite completa de 29 pruebas automatizadas (100% superadas) que verifican desde las reglas estructurales de Clean Architecture hasta endpoints HTTP de integración.

Principios Rectores del Starter Kit

  • Aislamiento de Negocio: El dominio es puro y agnóstico a bases de datos, APIs y frameworks externos.

  • Desarrollo Guiado por Estándares: RFC 7807 para errores, OpenAPI 3.1 con Scalar para documentación, OWASP Top 10 para seguridad perimetral.

2. Arquitectura del Sistema (Clean Architecture & CQRS)

La solución está organizada en 4 capas concéntricas con dependencia unidireccional de afuera hacia adentro:

+-------------------------------------------------------------------------------+ | BackendTemplate.Api | | Controladores REST, Middlewares OWASP, Scalar UI, CustomExceptionHandler| +-------------------------------------------------------------------------------+ │ ▼ +-------------------------------------------------------------------------------+ | BackendTemplate.Application | | Features (Commands & Queries), Pipeline Behaviors, Validadores Fluent | +-------------------------------------------------------------------------------+ │ │ │ (Implementa interfaces) ▼ ▼ +------------------------------+ +---------------------------------+ | BackendTemplate.Domain | | BackendTemplate.Infrastructure| | Entidades, Result, Error, | | EF Core 10, PostgreSQL, Identity├─────────────►│ Interfaces (ISoftDeletable) | +---------------------------------+ +------------------------------+

2.1. Responsabilidades por Capa

Proyecto Responsabilidad Dependencias Permitidas
BackendTemplate.Domain Núcleo de negocio, entidades, objetos de valor, tipos de error (`Error`, `ErrorType`) y contenedor `Result<T>`. Ninguna (0 dependencias)
BackendTemplate.Application Casos de uso (CQRS), contratos de interfaces (`IApplicationDbContext`, `IIdentityService`), validadores FluentValidation y pipeline behaviors. `Domain`
BackendTemplate.Infrastructure Acceso a datos con EF Core, PostgreSQL (`Npgsql`), ASP.NET Core Identity, JWT, interceptores de auditoría y migraciones. `Domain`, `Application`
BackendTemplate.Api Capa de presentación HTTP, controladores REST, endpoints, rate limiting, middlewares de seguridad y OpenAPI / Scalar. `Application`, `Infrastructure`

2.2. Pipeline Behaviors de MediatR

Cada comando o consulta despachada a través de `Mediator.Send(...)` atraviesa automáticamente 4 interceptores antes y después del Handler:

  1. `UnhandledExceptionBehavior`: Captura cualquier excepción no manejada y la registra de forma estructurada con Serilog.
  2. `LoggingBehavior`: Registra el inicio, identidad del usuario autenticado (`UserId`) y finalización de la operación.
  3. `PerformanceBehavior`: Monitorea tiempos de respuesta y emite una alerta estructurada (`LogWarning`) si el handler tarda más de 500 ms.
  4. `ValidationBehavior`: Ejecuta automáticamente todos los validadores FluentValidation registrados. Si hay errores, detiene el flujo y lanza `ValidationException` antes de consultar la base de datos.

2.3. Patrón Result & Error Fuertemente Tipado

Para eliminar el costo de rendimiento de las excepciones en flujos normales de negocio, se utiliza el patrón `Result<T>` con tipos semánticos `ErrorType`:

// Ejemplo de retorno en Handlers
if (student == null)
{
    return Result.Failure(Error.NotFound("Students.NotFound", $"Student with Id '{id}' was not found."));
}

student.Delete();
await _context.SaveChangesAsync(cancellationToken);
return Result.Success();

3. Seguridad, Autenticación & Identity

3.1. Flujo Criptográfico de Refresh Tokens

La autenticación utiliza JWT (HMAC-SHA256) con rotación de Refresh Tokens de alta seguridad almacenados en la base de datos:

🛡️ Detección de Token Reuse Attack (Anti-Replay)
Si un atacante intenta reutilizar un refresh token que ya fue marcado como `IsUsed = true`, el sistema detecta inmediatamente la anomalía de seguridad, revoca en cascada todos los tokens activos del usuario y devuelve `403 Forbidden`.

3.2. Claims Enriquecidos y RBAC

El Access Token emitido incluye información de contexto para evitar consultas repetitivas a la base de datos:

  • sub / NameIdentifier: Identificador único del usuario (GUID).
  • email: Correo electrónico verificado.
  • firstName / lastName: Nombre y apellido del usuario.
  • ClaimTypes.Role & roles: Lista de roles asignados (`Administrator`, `User`).

3.3. Middlewares de Seguridad OWASP

Encabezado de Seguridad Valor Configurado Ataque Mitigado
X-Content-Type-Options nosniff MIME type sniffing attacks
X-Frame-Options DENY Clickjacking & UI redressing
Referrer-Policy strict-origin-when-cross-origin Fuga de información confidencial en URLs
Permissions-Policy geolocation=(), camera=(), microphone=() Uso indebido de hardware del cliente
Content-Security-Policy Hardened con soporte para Scalar Docs Cross-Site Scripting (XSS) y code injection

3.4. Rate Limiting Anti-DDoS

Configurado a través de `RateLimiter` nativo de ASP.NET Core: particiona por dirección IP remota y restringe a 100 solicitudes por minuto, respondiendo `429 Too Many Requests` ante ráfagas no autorizadas.

4. Persistencia, Base de Datos & Resiliencia

4.1. Entity Framework Core 10 & PostgreSQL 17

La persistencia se gestiona con `ApplicationDbContext` implementando la interfaz contractural `IApplicationDbContext`. Cada entidad tiene su configuración Fluent API aislada en `Infrastructure/Persistence/Configurations/`.

4.2. Auditoría y Soft Delete Automático

El interceptor AuditableEntitySaveChangesInterceptor automatiza la trazabilidad:

  • Inserción: Asigna CreatedAt = UtcNow y CreatedBy = CurrentUserId.
  • Modificación: Asigna LastModifiedAt = UtcNow y LastModifiedBy = CurrentUserId.
  • Eliminación (Soft Delete): Modifica el estado a `Modified`, asignando IsDeleted = true, DeletedAt = UtcNow y DeletedBy = CurrentUserId.
  • Consultas automáticas: Todas las consultas excluyen registros eliminados gracias a builder.HasQueryFilter(e => !e.IsDeleted).

4.3. Resiliencia de Conexión con Polly v8

Se configuran reintentos automáticos con retroceso exponencial ante fallos transitorios de red o reinicios de PostgreSQL: 

npgsqlOptions.EnableRetryOnFailure(
    maxRetryCount: 3,
    maxRetryDelay: TimeSpan.FromSeconds(5),
    errorCodesToAdd: null);

5. Guía Paso a Paso: Cómo Agregar un Nuevo Módulo / Feature

A continuación se ilustra el procedimiento para crear un módulo de Productos (`Product`) en menos de 10 minutos:

Paso 1: Entidad de Dominio (`BackendTemplate.Domain/Entities/Product.cs`)

using BackendTemplate.Domain.Common;

namespace BackendTemplate.Domain.Entities;

public class Product : AuditableEntity, ISoftDeletable
{
    public string Name { get; private set; } = string.Empty;
    public string Sku { get; private set; } = string.Empty;
    public decimal Price { get; private set; }
    public bool IsDeleted { get; set; }
    public DateTime? DeletedAt { get; set; }
    public string? DeletedBy { get; set; }

    private Product() { }

    public Product(string name, string sku, decimal price)
    {
        Id = Guid.NewGuid();
        Name = name;
        Sku = sku;
        Price = price;
    }

    public void Delete(string? deletedBy = null)
    {
        IsDeleted = true;
        DeletedAt = DateTime.UtcNow;
        DeletedBy = deletedBy;
    }
}

Paso 2: Contrato y Caso de Uso (`BackendTemplate.Application`)

1. Agrega DbSet<Product> Products { get; } en IApplicationDbContext.cs.

2. Crea el Command, Validator y Handler:

public record CreateProductCommand(string Name, string Sku, decimal Price) : IRequest<Result<Guid>>;

public class CreateProductCommandValidator : AbstractValidator<CreateProductCommand>
{
    public CreateProductCommandValidator()
    {
        RuleFor(v => v.Name).NotEmpty().MaximumLength(150);
        RuleFor(v => v.Sku).NotEmpty().MaximumLength(50);
        RuleFor(v => v.Price).GreaterThan(0);
    }
}

public class CreateProductCommandHandler : IRequestHandler<CreateProductCommand, Result<Guid>>
{
    private readonly IApplicationDbContext _context;
    public CreateProductCommandHandler(IApplicationDbContext context) => _context = context;

    public async Task<Result<Guid>> Handle(CreateProductCommand request, CancellationToken cancellationToken)
    {
        var product = new Product(request.Name, request.Sku, request.Price);
        await _context.Products.AddAsync(product, cancellationToken);
        await _context.SaveChangesAsync(cancellationToken);
        return Result<Guid>.Success(product.Id);
    }
}

Paso 3: Controlador REST (`BackendTemplate.Api/Controllers/ProductsController.cs`)

[Authorize]
public class ProductsController : ApiControllerBase
{
    [HttpPost]
    [Authorize(Roles = "Administrator")]
    public async Task<IActionResult> Create([FromBody] CreateProductCommand command)
    {
        return HandleResult(await Mediator.Send(command));
    }
}
